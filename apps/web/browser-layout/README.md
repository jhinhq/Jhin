# App browser layout checks

Run `pnpm test:layout` from `apps/web` after installing the existing Chromium test browser (`pnpm test:e2e:browsers`). This starts a local Vite fixture on port 4178. No API, account, or production data is needed.

The fixture renders the production `AppLibrary`, global Tailwind stylesheet, and bundled fonts. Its outer dimensions mirror the Apps page's default `PageBody` and expanded `AppShell` sidebar. Keep those dimensions in sync if the shell changes. Only Next Link is substituted with an anchor because its router runtime cannot run standalone in Vite.

The 24 Chromium cases cover curated and synced catalog views, manager and read-only access, and 320/390/768/1024/1280/1440px widths. Fixtures include connected, reconnect-needed, unconnected, optional connection-method options, docs/details/actions, and a deprecated community app. Checks measure real element bounds, card/grid containment, header/control overlap, and document overflow. Screenshots are written under `test-results/layout` on every run; this directory is generated, not source.

The 13 assignment cases render the production `GiveToAgent` and `ConnectionAccessSummary` components inside the same wide `Dialog` used by app details, with a real React Query client. Playwright intercepts every API request using fixture data. At the same six widths, selecting Bisby and either read-only tools or all tools must post exactly the selected capabilities, each pinned to the Supabase connection. Tests verify saved counts, refreshed access summaries, expanded grant details, and no horizontal overflow or overlapping visible controls. A partial-failure case verifies that retry posts only the failed grant. No real connection or agent is modified.

The chat regression renders the actual `ChatThreadPage`, transcript, composer, data hooks, workspace context, and production query defaults. Only Next navigation is replaced with the fixture's chat pathname, alongside the existing Link substitution. At 390px and 1440px, a real composer submission runs longer than the 20-second post-send window; Playwright holds stale message/activity responses in flight, then reports completion through the independent detail request. The final reply and activity must appear without reload even after those stale responses arrive. Every API request is intercepted, with unexpected requests failing the test. Run just these cases with `node node_modules/@playwright/test/cli.js test --config browser-layout/playwright.config.ts chat-live-updates.spec.ts`. They intentionally spend at least 20.5 seconds each in the real browser timer window.

The six API-key cases render the production `ApiKeysPage`, `Dialog`, permission tree, workspace context, and query defaults against a 20-category mock catalog. At 390px and 1440px, lower category and individual checkboxes must retain focus and scroll position after selection. Preset checks cover Full access, Read-only, Clear, and unavailable scopes; the creation footer must stay visible while the lower permissions are on screen. Creation is intercepted and must send only the 38 available explicit scope keys, never a wildcard. The revealed key is an intentionally invalid fixture string; no real key is created. Run these cases with `node node_modules/@playwright/test/cli.js test --config browser-layout/playwright.config.ts api-keys.spec.ts`. The shared navigation fixture also exports inert router methods for the API page's shell imports; it does not replace the dialog or its lifecycle.

On Windows, if the pnpm test launcher fails, run `node node_modules/@playwright/test/cli.js test --config browser-layout/playwright.config.ts` directly. The fixture server uses the current Node executable and the Vite dependency already supplied by Vitest, without an intermediate pnpm launcher. The browser fixture deduplicates React and inlines the browser desktop flag just as the Next build does.

Some restricted Windows environments block Playwright's child-server teardown even with the direct Node launcher. If the runner stays open after the final case, stop it, start the fixture separately with `pnpm exec vite --config browser-layout/vite.config.ts`, and run the tests in a second terminal. The configuration reuses that server and does not own its shutdown; stop the fixture terminal after testing. This is a workaround for that environment, not a fix to Windows process teardown.

The terminal chat cases render the same actual chat page at 390px and 1440px. They show the requested command before output, then two changing stdout snapshots through the production polling hook, followed by a completion that overtakes a stale in-flight request. Exit status, stderr, and output must survive a reload without duplicate cards or horizontal overflow. Run with `node node_modules/@playwright/test/cli.js test --config browser-layout/playwright.config.ts chat-terminal.spec.ts`; running and completed screenshots are saved to the test output directory. All execution data is mocked and no command is actually run by this fixture.

This is a responsive component regression check. It does not replace authenticated application or OAuth end-to-end tests.
