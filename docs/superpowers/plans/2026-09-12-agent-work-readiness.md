## Required outcomes

1. A credential-only Ghost request securely captures the credential and asks for the actual Ghost Admin URL before any external request, research, terminal work, or unrelated delegation. Missing required time/timezone, audience, or publication authority is resolved before the corresponding work starts. Required questions never turn into permission to guess after a timeout.
2. Agent, team, and company variables support create, list, read, replace, and delete from the UI and authorized agent tools. Non-sensitive values are readable. Sensitive values are encrypted, absent from every public response after setting, and represented to models by authorized opaque references. Scope membership and write grants are enforced when used, not just when listed. Changing scope is explicit; revision checks prevent lost updates.
3. Sensitive chat input is captured before message/task/title/journal/Temporal persistence. Create, send, steering, queued edits, and submission retries share the same intake boundary. Typed secure input supplements detection of recognizable keys and explicit secret assignments. Sensitive values are not stored in memory, copied into colleague instructions, or returned by variable tools.
4. Team membership and role relevance guide collaboration. Agents can intentionally request company-wide expertise when needed, while routine marketing work stays in Marketing. Removed team memberships confer no access. Repeated identical failed work is bounded and is not restarted without new information.
5. Natural-language recurring requests create real durable schedules with an explicit IANA timezone, next occurrence, pause/resume/update/delete controls, execution history, and idempotent dispatch. Restarts, duplicate ticks, overlaps, and DST are tested. Scheduled runs preserve the standing brief and publishing restrictions.
6. Ghost has native authenticated read, draft create/edit, review, and publish operations. Admin keys produce short-lived signed Admin API tokens inside the worker. URLs are never guessed; credentials stay at an approved origin. Blogger can create drafts; only the designated Marketing Director may approve and publish the exact reviewed version. Changes after review invalidate publication readiness. Neither a generic status update nor another agent may bypass this rule.
7. Memories retain supported preferences, facts, and standing briefs with provenance and useful summaries. Unsupported assertions about successful setup are excluded; duplicates, superseded facts, and summary freshness are handled explicitly. Sensitive facts remain excluded across all scopes.
8. Real API, browser, model, Temporal, and Ghost-server scenarios prove the full workflows. Mocked providers support failure coverage but do not substitute for live integration. Production credentials are not sent to guessed hosts and no sample post is published on the user's real blog during testing.
